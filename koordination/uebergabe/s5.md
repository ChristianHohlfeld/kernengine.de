## Erkenntnisse, die man sonst neu erarbeiten müsste
- Der Konverter sieht die Klassen des Headers gar nicht: `run_clang` dumpt nur Deklarationen, deren qualifizierter
  Name `sc::`, `kern::` oder einen --program-Raum enthält. Die Klassen stehen in `kern_blueprint_<hash>::`, die Namen in
  `blueprints::`. Er versucht also nicht, sie zu konvertieren (keine Ausnahme-Regel nötig). Eine Funktion, die sie
  nennt, sieht aber nur ins Leere zeigende Ids und wartet. Genau dort setzt die Fähigkeit an.
- Ohne Header parst clang game.cpp und game_net.cpp nicht. `run_clang` liefert dann nichts, die Game-Teile dieser
  Dateien fehlen, und ein voller Lauf würde das Level beschneiden. Darum erzeugt der Konverter den Header jetzt selbst,
  sobald es Program-Actors gibt. mag (lauf2.sh) klont frisch und baut vorher nicht.
- `#include "…"` sucht zuerst neben der Datei. Ein alter src/level_blueprints.h aus einem lokalen Build schlägt das
  -I des Laufs; deshalb vergleicht der Lauf beide und bricht bei Abweichung ab.
- Das Objekt, an das gebunden wird, ist das Objekt der Laufzeitinstanz (Kleber `<Name>_Native::self`). Jedes Actor
  mit Logik (auch die Bibliotheken in Source) bekommt in GameWorld eine Instanz und läuft nativ, wenn der Hash passt.
  Ein Test braucht eine Laufzeit, in der die Actors laufen: `RuleBlueprint("qr_code_cpp", nullptr, true, {"qr_code"})`
  und dann bind_blueprint je Klasse. blueprints::bind gibt in so einer Teil-Laufzeit false, weil die anderen Klassen
  fehlen.
- Die Pointer aus bind gelten nur, solange die Laufzeit lebt (wie bei ActorBlueprint): in Tests jedes Mal neu binden.
- Schleifenwächter: `kern_pass` braucht für den Fall über der Grenze `runtime->pass(*instance)`. Ein Objekt ohne Welt
  hat keine Grenze. Die Grenze 2e9 gilt jetzt im ganzen Spiel, also auch für die Regel-Blueprints.
- Woher die 17× kommen, ist nicht untersucht (Sache von p). Verdacht: Formeln über `double` mit `kern::to`, Listen
  mit Grenzprüfung, `List<Bool>` statt Bitvektor, Listen, die je Aufruf neu gebaut werden.
- Das Level schreibt der Konverter mit `json.dumps(indent=1)`, blueprint_cpp mit `json::stringify` – die Formate
  unterscheiden sich. Den Ordner deshalb nur als Zeile im Text ändern (so gemacht), nicht per Python neu schreiben.

## Fallen
- `CLASSES` in cpp_to_blueprint.py ist eine globale Liste; main setzt sie vor dem Pool (fork erbt sie). Ein Test bindet
  den Header beim Namen ein (`#include "level_blueprints.h"`), run_tests.sh findet ihn über -Isrc.
- Wer eine weitere Datei umschaltet: Actor-Ordner auf Program (Textzeile), C++ und tests/converted/test_<datei>*.cpp
  löschen, Aufrufer auf `kern::logic::blueprint<blueprints::X>()`; prüfen, ob die benutzten shapes und Funktionen in
  Source bleiben (kept_by_others bricht sonst ab).
